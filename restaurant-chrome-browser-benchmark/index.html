How The Test Was Conducted

This run used the installed Google Chrome binary at /Applications/Google Chrome.app/Contents/MacOS/Google Chrome, launched by Playwright. Chrome was run headless at 1440x1000. Login/setup was excluded from measured admin timings. HTTP non-2xx/aborted rates include redirects and status-0 browser cancellations; user-visible flow failure is reported separately in the Success column.

  1. Create a fresh small restaurant WordPress site for one database variant: 10 pages, 6 blog posts, 36 seeded comments, 8 seeded reservation requests, and 4 users.
  2. Start local nginx and PHP-FPM for that site, with no page cache, CDN, or object cache enabled.
  3. Open Google Chrome and create a fresh browser context for each measured repetition.
  4. For admin flows, log in once as the administrator before the measured flow and save the authenticated Chrome session.
  5. Homepage flow: visit the restaurant homepage, wait for the document and network to settle, then scroll down and back up.
  6. Menu page flow: visit the restaurant menu page, wait for content and assets to settle, then scroll the menu content.
  7. Blog post flow: visit a rotating published restaurant blog post, wait for content and assets to settle, then scroll the post.
  8. Frontend XHR flow: visit the homepage with ?bench_xhr=1; benchmark-only JavaScript fires menu, availability, REST search, and page/post fetch requests; Chrome waits for all of them to finish.
  9. Reservation flow: visit the reservations page with the benchmark form enabled, fill name/party/marker fields, click Request table, and wait for the reservation REST response.
  10. Post editor flow: open wp-admin/post.php?post=<benchmark post>&action=edit, wait for the block editor shell/data to settle, then click inside the editor canvas.
  11. Site editor flow: open wp-admin/site-editor.php, wait for the editor shell/canvas to settle, then click inside the Site Editor shell.
  12. Pages admin flow: open the Pages list in wp-admin and run a simple pages search.
  13. Repeat each flow 20 times, record Chrome navigation timing, FCP/LCP/CLS, request timings, XHR/fetch timings, console errors, screenshots, and WordPress request-log query timing.
  14. Stop the server, delete the active site/database, and repeat the same process for the next database variant.
