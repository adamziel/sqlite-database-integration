How The Test Was Conducted

This run used the installed Google Chrome binary at /Applications/Google Chrome.app/Contents/MacOS/Google Chrome, launched by Playwright. Chrome was run headless at 1440x1000. Login/setup was excluded from measured admin timings. HTTP non-2xx/aborted rates include redirects and status-0 browser cancellations; user-visible flow failure is reported separately in the Success column.

  1. Create a fresh 5GB WooCommerce WordPress site for one database variant, with the same product, customer, order, and postmeta fixture inputs.
  2. Start local nginx and PHP-FPM for that site, with no page cache, CDN, or object cache enabled.
  3. Open Google Chrome and create a fresh browser context for each measured repetition.
  4. For admin flows, log in once as the administrator before the measured flow and save the authenticated Chrome session.
  5. Shop catalog flow: visit the WooCommerce shop page, wait for the document and network to settle, then scroll down and back up.
  6. Product detail flow: visit a published product page, wait for the product content and assets to settle, then scroll the product page.
  7. Frontend XHR flow: visit the shop page with ?bench_xhr=1; benchmark-only storefront JavaScript fires Woo Store API, WordPress REST search, cart, and cart-fragment fetch/XHR requests; Chrome waits for all of them to finish.
  8. Checkout flow: visit a product page, click Add to cart, open Cart, open Checkout, fill billing fields, click Place order, and wait for the order-received page.
  9. Post editor flow: open wp-admin/post.php?post=<benchmark post>&action=edit, wait for the block editor shell/data to settle, then click inside the editor canvas.
  10. Site editor flow: open wp-admin/site-editor.php, wait for the editor shell/canvas to settle, then click inside the Site Editor shell.
  11. Woo orders admin flow: open the WooCommerce orders list in wp-admin and run a simple orders search.
  12. Repeat each flow 5 times, record Chrome navigation timing, FCP/LCP/CLS, request timings, XHR/fetch timings, console errors, screenshots, and WordPress request-log query timing.
  13. Stop the server, delete the active 5GB site/database, and repeat the same process for the next database variant.
